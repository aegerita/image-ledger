# OBS-5: Image Ledger and a general image model

The user selected **Image Ledger**. The public plugin ID is `image-ledger`; active state, CSS, command IDs, test markers and snapshots use that name. The private package is `obsidian-image-ledger`.

## Model

- An image owns its ID, bytes/hash, description, import time and source capture metadata.
- `sourceNotes` / `source_notes` are references from arbitrary Markdown notes. An image can have several references or none.
- Images have no journal date or substitute note-date field. A note's filename does not become image metadata.
- Fresh installs use flat `images/` and `image-records/` folders. Import-year and note-year grouping are optional storage policies. The destination is pinned when a capture is staged.
- Schema 2 uses `type: image-ledger-image`, `source_notes`, and `image-ledger:record` snapshot markers. The library is `image-library.base`; transient state is `.image-ledger/`.

## Compatibility

Legacy names remain in compatibility readers and historical evidence. Valid old records are upgraded at their existing paths only after preserving an untouched original in `.image-ledger/legacy-records/`. That original retains the old note date and metadata. The first backup is never overwritten. A migration failure leaves the old record available for retry. Prior caption snapshots survive migration until normal description synchronization finishes.

Legacy staged captures remain recoverable from their original paths. The installer copies old settings only when new settings are absent, preserves the old plugin files, and disables the old handler only when `--enable` is requested. Existing installations keep their previous storage policy. No personal-vault installation or migration was performed for this task.
