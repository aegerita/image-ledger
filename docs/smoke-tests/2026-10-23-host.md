# Repeatable Obsidian host smoke test — 2026-10-23

`npm run test:obsidian` now runs the live integration checks through Obsidian's CLI and the loaded app. Two consecutive fresh-vault runs passed on Obsidian 1.14.5 in **13.620 seconds** and **4.529 seconds**, including build and vault setup. `npm test` also passed all **51 tests**.

## What made the earlier run slow

The earlier manual run mixed native UI control, repeated retries after stale screenshots/window targeting failures, one-off API scripts and manual evidence collection. It had no overall time budget. The API assertions themselves were fast; the repeated control and setup work dominated. Continuing those retries instead of switching promptly was a workflow mistake.

The repeatable runner also exposed concrete initialization problems: a new vault first asks whether to trust its plugins; the CLI can return an error with exit code zero; and CLI handlers appear asynchronously during startup/reload. The runner now handles those cases explicitly. A Bases image link can replace its tab, so the runner reopens the Base before checking its journal link.

## Scope and limits

One fresh generated vault per run contains only synthetic notes, known JPEG/PNG fixtures and the current plugin build. Before enabling plugins, the runner verifies the CLI's exact target path, generator marker, fixtures, sole-plugin allowlist and artifact hashes. It changes restricted mode only for that generated vault. Each host invocation checks the canonical vault path again.

Eight real-host checks cover JPEG capture/EXIF, cross-year duplicate reuse, actual Bases caption editing and links, drop-handler insertion after note switching, Describe later, the edit-description command, paste staging with a caption open, reload/recovery under the same UUID, and the clean audit. The final independent filesystem assertions check payload bytes and hashes, metadata, frontmatter/snapshots, XMP, backlinks, one current embed per note and empty staging.

The command has a **90-second deadline**, including its build. Individual startup waits and host checks are bounded. Missing acknowledgments, wrong vaults, changed fixtures/builds, stale receipts, failed assertions and CLI errors cause a nonzero exit. Failed vaults and receipts remain available. There is no fallback into native computer control.

These are real app/plugin/editor/widget operations with generated paste/drop events. They do not test native macOS clipboard conversion or Finder gestures. The runner uses private APIs and Bases DOM selectors; incompatible app updates may require changes, and should fail promptly. The app must already have an initialized open vault and its CLI enabled.

[JSON evidence](2026-10-23-host.json) preserves the measured runs, check outcomes, audit notices and payload identities. Each generated vault also retains `.journal-media-smoke/` receipts and the copied host script.
